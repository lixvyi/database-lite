# 拾页 MiniDB 学生测试集

## 一 文档用途

本文档是项目组在验收前自行设计的统一测试集，用于检查SQL编译器、操作系统页式存储和数据库引擎能否稳定运行，并为现场答辩提供预设输入、预期结果和代码证据。

现场手敲时使用 `docs/答辩现场所有输入.txt`；本文档用于向老师说明每个输入为什么测试、预期看到什么、实际结果如何以及由谁负责。

## 二 测试基本信息

| 项目 | 内容 |
|---|---|
| 项目名称 | 拾页 MiniDB |
| 测试范围 | SQL编译器、页式存储、缓存、数据库执行引擎、系统集成 |
| 操作系统 | Windows |
| Python | Python 3.11及以上 |
| 测试入口 | MiniDB实验台、OS仿真台、`minidb_cli.py`、`os_sim_cli.py`、`unittest` |
| MiniDB测试目录 | `defense_final_01`，重复测试时更换末尾编号 |
| OS测试目录 | `defense_os_01`，重复测试时更换末尾编号 |
| 测试数据 | 每轮使用新目录，避免旧表、旧页或损坏数据影响结果 |

## 三 测试人员分工

| 负责人 | 负责模块 | 测试重点 |
|---|---|---|
| 成员A | SQL编译器 | Token、AST、语义检查、逻辑计划、规则优化、编译错误 |
| 成员B | 操作系统页式存储 | 页面分配释放、4KB读写、LRU/FIFO、pin、dirty、WAL、Checkpoint |
| 成员C | 数据库引擎与系统集成 | CRUD、执行算子、Record、RID、SlottedPage、Catalog、持久化 |

## 四 测试结果填写规则

- `通过`：实际结果与预期结果一致。
- `失败`：功能未完成、程序异常或结果错误。
- `阻塞`：测试环境或外部条件导致无法执行，需要写明原因。
- 每次正式验收演练后应更新“实际结果”和“结论”，不能只填写预期结果。
- 如果运行目录中已经存在同名表，应更换目录编号，不把“表已存在”误判为项目缺陷。
