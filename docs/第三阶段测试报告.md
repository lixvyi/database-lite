# 第三阶段测试报告

## 复现命令

```powershell
py -3 -m unittest discover -s tests -v
```

本轮在 Windows/Python 环境实测 25 个测试，全部通过，总耗时约 2.36 秒。毫秒数据会随机器负载变化，验收以结果断言和 I/O 计数为准。

## 指导书指定正确性场景

| 场景 | 输入/做法 | 预期与实测 |
|---|---|---|
| 创建表 | `CREATE TABLE bulk...` | 返回创建成功；目录页出现列元数据 |
| 重复建表 | 再次创建 `bulk` | 抛出 SemanticError，不覆盖原表 |
| 大量插入 | 单次提交 300 条 INSERT | 全部可读，数据跨越至少两个已分配页 |
| 条件准确性 | `WHERE id>=290 ORDER BY id DESC` | 精确返回 299～290 共 10 行 |
| 删除后查询 | 删除 `id>=295` 后复查 | 影响 5 行；只剩 290～294 |
| 重启持久性 | close 后用同一目录新建 Database | 表结构和 290～294 仍可查询 |
| 元数据也走页 | 检查文件与页 0 | 不存在 `catalog.json`；页 0 前四字节为 `CAT1` |
| 系统目录查询 | `SELECT ... FROM pg_catalog` | 返回表名、列名、类型、长度、首页号 |
| UPDATE 扩展 | `SET score=score+5 WHERE id=2` | 只更新一行，其他行不变 |
| ORDER BY 扩展 | `ORDER BY score DESC,name ASC` | 多列顺序与方向正确 |

## 异常与可靠性场景

| 测试 | 证明内容 |
|---|---|
| 非法字符/错误 SQL | 错误类型带行列号和期望符号 |
| 缺失列、类型不匹配 | 执行前由语义层拒绝 |
| 修改 `pg_catalog` | 明确提示系统目录只读 |
| WAL durable_lsn 落后 | 脏页刷回被屏障阻止 |
| 未 checkpoint 模拟崩溃 | 新 StorageService 自动重放 WAL |
| LRU/FIFO 对照访问序列 | 驻留页集合不同，证明策略实际生效 |
| 同页热读 100 次 | 第一次 miss、随后 99 次 hit |
| 1000 个队列任务 | 全部完成，最大等待深度不超过 64 |

## 结论

测试覆盖编译、执行、页式存储、缓存、WAL、系统目录和重启边界。当前结果证明的是教学型单机数据库核心链路，不外推为分布式数据库、完整事务系统或生产级 SQL 兼容性。
