# 三人分工与接口边界

三名成员分别对应课程的三个部分。每个人主讲一个模块，同时必须理解完整主线：`SQL → Token → AST → Semantic → Plan → Executor → Storage → PageFile`。

## 成员 A：SQL 编译器

负责 `minidb/tokens.py`、`lexer.py`、`ast.py`、`parser.py`、`semantic.py`、`plan.py` 和 `optimizer.py`。

必须能解释：Token 的四项信息；行列号如何更新；递归下降与左递归；NOT、比较、AND、OR 的优先级；AST 与 Token 的区别；Catalog 名字绑定；类型、列数和 `VARCHAR(n)` 检查；SELECT 如何生成 SeqScan、Filter、Project；常量折叠为何等价。

本部分只保留两个扩展：`UPDATE` 和 `ORDER BY`。不实现 EXPLAIN、JOIN、GROUP BY 和 SQL NULL 字面量。

## 成员 B：操作系统页式存储

负责 `os_sim/page_file.py`、`cache.py`、`service.py`、`wal.py`、`interfaces.py`、`os_sim_cli.py`，以及存储模块测试。

必须能解释：固定 4KB 页；`page_id × 4096` 文件偏移；页分配、释放和复用；LRU 与 FIFO；hit、miss、dirty、pin；脏页淘汰；统一 PageStore 接口；缓存统计和替换日志。

本部分只保留两个扩展：64 页 Extent 分配，以及页级 redo WAL/Checkpoint。校验和与双控制文件属于页文件正确性保护，不单独宣传为扩展。不实现查询调度器、Undo、MVCC 和 B+ 树。

## 成员 C：数据库引擎与系统集成

负责 `minidb/execution.py`、`catalog.py`、`engine.py`、`minidb/storage/`、`minidb_cli.py`、MiniDB Web API 和端到端测试。

必须能解释：Plan 如何选择 Executor；SeqScan、Filter、Project 的数据流；Row 编解码；RID；SlottedPage；TableHeap 页链；逻辑删除；系统目录为何从页 0 启动并如何跨页；重启后如何恢复表结构和数据。

数据库引擎只实现与 SQL 编译器相同的两个扩展：UPDATE 和 ORDER BY。不实现权限、查询并发、索引、事务回滚和代价优化。

## 共同责任

- 成员 A 输出稳定的 PlanNode，不读取物理页。
- 成员 B 输出稳定的 PageStore 接口，不理解 SQL 和 Schema。
- 成员 C 负责连接两侧，不能绕过 Buffer/StorageService 直接访问文件。
- 三人共同维护验收矩阵、隐藏测试、错误案例、演示脚本和报告截图。
- 每人都要能在一分钟内定位四条必做 SQL 的核心代码和测试。
