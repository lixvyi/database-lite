# 操作系统模块代码答辩导读

## `page_file.py`

- `PAGE_SIZE=4096` 表示数据文件中的每个页就是完整 4KB；generation 和 CRC 放在双份控制文件，数据库可完整使用页内字节。
- `_load_control` 读取两份控制文件，忽略损坏副本并选 generation 最大者。
- `_save_control` 先写临时文件并 fsync，再原子替换，避免半写 JSON。
- `_grow_extent` 一次将表空间扩展 64 页，同时扩展 allocation bitmap。
- `_validate` 是所有读写释放操作的统一越界/未分配检查。
- `read_page/write_page` 只有这里执行 `seek(page_id*4096)`，物理映射不会散落；`_migrate_v1_pages` 只负责旧 4076B payload 格式的一次迁移。

## `cache.py`

- Frame 保存 payload、generation、dirty、pin_count、page_lsn。
- `fetch` 命中 LRU 时 move_to_end，FIFO 命中不移动；这是两策略的唯一关键差异。
- `update` 先 `wal.append_page`，成功 fsync 后才修改内存 frame。
- `_flush` 先比较 page_lsn 与 durable_lsn，障碍通过后才调用磁盘写。
- `_evict` 只选 pin_count=0 的 frame，dirty victim 先刷回。

## `wal.py` / `service.py`

- WAL 每条记录带 LSN、page_id、generation、after-image 和 CRC。
- `records` 逐行校验，遇到崩溃产生的不完整尾记录即停止。
- `_recover` 只处理 checkpoint 后的日志，且只在磁盘 generation 更旧时重放。
- `write_page` 负责脏页比例阈值；`checkpoint` 和正常关闭负责全量一致点。

## 教师可能追问

1. 为什么 WAL 必须先于数据页刷盘？
2. 为什么 checkpoint 不是每次写都执行？
3. LRU 遇到大范围顺序扫描会有什么污染，如何改进？
4. control 两副本都损坏怎么办？
5. redo after-image 为什么幂等，空间代价是什么？
6. 进程内锁为何不能替代跨进程文件锁？
