# 一周三人实训总报告

## 一、目标与范围

三人用一周完成教学型小型数据库，主链路为 SQL 文本 → Token → AST → 语义检查 → 逻辑计划 → 执行器 → 槽页 → 缓存/WAL → 4KB 页文件。基础功能严格覆盖 CREATE TABLE、INSERT、SELECT、DELETE、页式存储、缓存管理、执行器和持久化。

扩展保持克制：SQL 编译器与数据库引擎共同选择 UPDATE、ORDER BY；操作系统存储选择 64 页 Extent、页级 redo WAL/Checkpoint。权限、查询调度、JOIN、GROUP BY、索引、Undo/MVCC 不在验收范围。

## 二、三人分工

- 成员 A：SQL 编译器。负责 Lexer、Parser、AST、Semantic、Catalog 接口、Plan 与错误定位。
- 成员 B：操作系统存储。负责 4KB PageFile、页分配释放、LRU/FIFO Cache、WAL、Checkpoint 与恢复。
- 成员 C：数据库引擎和集成。负责 Executor、TableHeap、RecordCodec、系统目录页、CLI/API、端到端持久化测试。

每人主讲自己的模块，但必须能沿统一数据流解释相邻接口。详细到函数的职责见 `三人分工.md`。

## 三、一周计划

1. 第一天：冻结语法、页接口、Plan 接口和验收用例。
2. 第二天：成员 A 完成词法/语法；成员 B 完成页文件与分配；成员 C 完成行页布局。
3. 第三天：完成语义/计划、LRU/FIFO、TableHeap 和基础执行。
4. 第四天：打通四条基础 SQL、系统目录页和重启持久化。
5. 第五天：只实现四项已选扩展并补边界测试。
6. 第六天：全量测试、故障恢复、逐文件讲解和现场改题训练。
7. 第七天：冻结代码，按验收矩阵逐项演示，准备回退数据目录。

## 四、验收证据

运行 `py -3 -m unittest discover -s tests -v` 验证编译、语义、计划、CRUD、槽页、缓存、WAL、系统目录多页扩展和重启恢复。运行 `py -3 minidb_cli.py --inspect --file demo.sql` 可展示编译全过程；运行 Web 实验台可观察页目录、缓存命中、替换事件和 checkpoint。

## 五、设计结论

项目的重点不是 SQL 数量，而是每层职责清楚、所有数据与元数据都经统一页接口持久化、错误可定位、测试可复现。这个范围能在严格答辩中逐层追踪，也保留了少量容易解释和现场修改的扩展。
