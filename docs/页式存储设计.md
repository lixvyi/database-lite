# 页式存储与逻辑—物理映射

## 物理文件

集成主路径中的 `storage/tablespace.dat` 是连续二进制页文件，每页固定 4096 字节。物理映射公式是：

```text
byte_offset = page_id × 4096
```

因此第 0 页位于 `[0,4096)`，第 1 页位于 `[4096,8192)`。`PageFile.read_page/write_page` 只依据此公式定位；旧 `minidb/storage/disk.py` 保留为第一阶段教学对照，不属于当前集成主路径。

## Slotted Page

```text
低地址                                                         高地址
+----------+--------------------+-----------空闲-----------+---------+
| PageHeader | Slot 0 | Slot 1 | ...                      | Records |
+----------+--------------------+--------------------------+---------+
             free_start →                         ← free_end
```

页头保存魔数、页号、槽数量、空闲区边界和下一页号。槽目录保存 `(record_offset, record_length)`。新增槽从前向后增长，变长记录从页尾向前增长；删除把长度改为 0，形成 tombstone。RID 是 `(page_id, slot_id)`，即一行在磁盘中的物理地址。

## 行编码

每行依次编码为字段数量、NULL bitmap 和字段值。`INT` 用 8 字节小端整数；`VARCHAR` 用 4 字节长度前缀加 UTF-8 字节。因此中文不是“按字符定长”，而是先编码成 UTF-8，再按字节长度读取，能够无损保存多语言文本。

## 逻辑表如何找到物理页

Catalog 自身保存在物理页 0，保存列结构和 `first_page`。用户表的第一页通过页头 `next_page` 连成单向页链：

```text
table name → pg_catalog(page 0).first_page → Page 3 → Page 8 → Page 11 → NO_PAGE
```

顺序扫描沿页链读取槽位。新增记录优先寻找有空间的现有页；没有空间时分配新页，并把旧尾页的 `next_page` 指向新页。

## 缓存与操作系统联系

StorageService 是独立的用户态 OS 仿真实体，容量固定并支持 LRU/FIFO。`pin_count > 0` 的页不能淘汰；脏页在淘汰、阈值、后台写或 checkpoint 时写回，且必须先满足 WAL 屏障。实际路径是：执行器 → TableHeap → OSBufferAdapter → StorageService → PageCache/WAL → PageFile。
