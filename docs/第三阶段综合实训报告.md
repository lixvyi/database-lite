## 一、实践目的

贯通 SQL 语言处理、操作系统页式存储和数据库执行三个模块，完成能交互、能持久化、能解释执行过程的小型数据库原型。

## 二、实践内容

实现词法、语法、语义和逻辑计划；实现 4KB 页、LRU/FIFO、脏页和统一页接口；实现槽页系统目录、CreateTable、Insert、SeqScan、Filter、Project 与 DELETE。SQL 与执行只扩展 UPDATE、ORDER BY；存储只扩展 Extent 和页级 redo WAL/Checkpoint。

## 三、实践方法

系统采用分层接口。编译器输出 PlanNode；执行器以 iterator model 拉取行；TableHeap 将逻辑表转换为页链与 RID；OSBufferAdapter 只调用 PageStore；StorageService 内部实现缓存、WAL 和物理文件。完整原理和取舍见《数据库系统集成设计》与《操作系统模块设计取舍》。

## 四、实践步骤

1. 定义 MiniSQL 文法、Token 和 AST。
2. 完成表列绑定、类型检查和计划生成。
3. 实现固定页、槽目录、行编解码与页链。
4. 实现缓存替换、WAL 屏障、刷脏和恢复。
5. 将 Catalog 实现为页 0 起始的特殊槽页表，并把执行器接到统一页接口。
6. 实现 UPDATE、ORDER BY 和只读 `pg_catalog` 查询。
7. 运行单元、端到端、多页目录、崩溃恢复与 HTTP 测试。

## 五、实践结果

当前自动测试共 51 项全部通过，其中按三人职责新增 24 项课程标准验收测试。系统可处理多语句输入、300 行跨页数据、多页系统目录、条件查询、逻辑删除和重启持久化；能展示 Token、AST、语义检查结果、优化前后计划、结果、页目录和缓存/WAL 指标。详细用例和结果见《第三阶段测试报告》；界面截图位于 `docs/assets/`。

## 六、实践结论

实验表明三门课程的核心概念能够通过稳定边界组合：Catalog 同时承担语义绑定与物理页入口，执行计划隔离 SQL 与执行，PageStore 隔离记录组织与 OS 可靠 I/O。缓存通过命中计数证明减少磁盘访问，WAL-before-data 与重启重放证明页级恢复有效。

## 七、实践小结

本项目的难点不是增加 SQL 关键字，而是维持跨层不变量：页必须恒为 4096 字节、RID 必须可解释、目录先于用户表可定位、脏页不得越过 WAL、重启后逻辑模式必须仍能找到物理首页。尚待改进的是页压缩、事务回滚、行级并发、索引和代价优化，这些被明确保留为后续工作。
