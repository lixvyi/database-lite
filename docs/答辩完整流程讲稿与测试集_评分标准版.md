### 成员A讲稿

> 老师好，我们实现的是一个教学型单机MiniDB。项目把编译原理、数据库和操作系统连接成一条真实可运行的链路。SQL首先经过词法分析、语法分析和语义分析，生成逻辑计划并进行规则优化；数据库执行器再把计划转换成行和槽页操作；底层通过统一PageStore接口进入4KB页文件、缓存和WAL。
>
> 我们按三个模块分工。我负责SQL编译器，成员B负责操作系统页式存储，成员C负责数据库执行引擎与系统集成。三个模块分别通过PlanNode、Catalog和PageStore接口连接，任何一层都不会越过接口直接操作另一层内部实现。
>
> 项目的基本SQL范围包括CREATE、INSERT、SELECT和DELETE，同时只保留少量容易验证的扩展：SQL与执行部分实现UPDATE和ORDER BY，存储部分实现Extent分配和页级redo WAL及Checkpoint。JOIN、GROUP BY、索引、事务回滚和MVCC不在本次实现范围内。

如果老师问“为什么要分层”，回答：

> 分层能让每个模块只关心自己的抽象。Parser只构造AST，Semantic只通过Catalog查名字和类型，Executor只执行Plan，OS层只处理固定大小页。修改缓存策略不会影响SQL语法，增加SQL语句也不需要修改PageFile。

### 2 测试A1 编译完整SQL

先在CLI创建一张专用表，成员A手敲：

```powershell
py -3 minidb_cli.py --data defense_final_01 --sql "CREATE TABLE t(id INT,name VARCHAR(10),score INT);"
```

预期出现：

```text
table 't' created
```

然后在MiniDB实验台手敲：

```sql
SELECT name FROM t
WHERE 1=1 AND score>10+8
ORDER BY score DESC;
```

点击“编译并检查”，按页签依次展示：

1. Token：关键字、标识符、整数、运算符、分隔符和行列号。
2. AST：根节点是SelectStmt，WHERE内部是BinaryExpr。
3. 语义：显示通过，说明表、列和WHERE布尔类型合法。
4. 原计划：`Project → Sort → Filter → SeqScan`。
5. 优化后：`1=1 AND X`被化简，`10+8`变成`18`。

成员A讲稿：

> Lexer从左到右扫描字符，每个Token保存类型、原始词素、转换后的值和起始行列。Parser采用手写递归下降，每个文法非终结符对应一个方法，并用不同层的方法实现乘除、加减、比较、NOT、AND、OR的优先级。Parser输出的是AST，AST描述SQL结构，还没有决定执行步骤。
>
> 语义分析通过Catalog检查`t`表以及`name`和`score`列是否存在，并递归推导表达式类型。比较表达式得到BOOL，因此能够作为WHERE条件。PlanBuilder生成Project、Sort、Filter、SeqScan计划树；执行数据从最下方SeqScan流向根节点。
>
> 优化器使用深复制保留原计划，再递归折叠常量。`10+8`与任何一行数据无关，所以提前变成18；`1=1`变成True，`True AND X`等价于X。这些改写不改变查询结果，只减少运行时重复计算。

### 3 成员C同步讲稿

> INSERT首先根据Schema建立完整行字典，没有指定的列初始化为None，表达式求值后交给TableHeap插入。RecordCodec按照Schema编码，SlottedPage返回槽号，最终RID由页号和槽号组成。
>
> SELECT计划通过`Executor._rows()`递归执行。SeqScan从Catalog中的first_page开始沿页链读取，Filter逐行计算WHERE，Sort暂存候选行并稳定排序，Project只保留查询列。
>
> UPDATE使用修改前的original行计算所有右侧表达式，再写入updated行，避免多列赋值互相污染。如果更新后的记录在原槽位置放不下，TableHeap会插入新RID，再删除旧RID。
>
> DELETE先取得待删除RID列表，再逐条执行逻辑删除，避免边扫描边修改槽目录。写操作使用表级写锁，SELECT使用读锁，锁在finally中释放。

### 4 测试B3 缓存机制

打开OS仿真台，按以下顺序操作：

1. 把缓存容量设置为较小值，例如2或3页。
2. 分配至少3页。
3. 读取页0、页1，再次读取页0，最后读取页2。
4. 观察hit、miss、resident和eviction事件。
5. 切换LRU和FIFO，用相同访问序列重新测试。

讲稿：

> 第一次读取页0和页1是miss，再次读取页0是hit。缓存已满后读取页2需要淘汰。LRU命中页0后会把它移动到最近使用位置，因此更可能淘汰页1；FIFO命中不会改变进入顺序，因此更可能淘汰最早进入的页0。pin_count大于0的frame不能被淘汰；如果全部frame都被pin，系统会明确报告缓存压力错误。

注意：OS CLI每条命令结束时会正常close并推进一致状态，不适合观察“尚未刷回的dirty帧”。dirty、pin和替换过程要在持续运行的OS仿真台中展示。

### 5 测试B4 WAL和Checkpoint

在OS仿真台中：

1. 选择一个已分配页。
2. 使用“修改内存页”写入新内容。
3. 观察WAL LSN增加、frame变成dirty。
4. 点击Checkpoint。
5. 观察dirty清零，Checkpoint LSN追上WAL LSN。

CLI备用命令：

```powershell
py -3 os_sim_cli.py --data defense_os_01 checkpoint
```

成员B讲稿：

> 项目采用页级redo WAL，日志保存完整4KB after-image。更新页面时先把日志追加并持久化，再允许脏页写入数据文件，这就是WAL-before-data规则。Checkpoint先刷新脏页，再推进检查点LSN；如果反过来，恢复程序可能误以为数据已经落盘而跳过必要重放。重启时系统比较日志记录和磁盘页面generation，只重放磁盘较旧的页面，因此重复恢复也是幂等的。


只改KEYWORDS只能完成词法识别，不能说整个SQL功能已经完成。

### 2 增加一个比较运算符

检查顺序：

```text

→ execution.py的OPS

```

### 3 修改缓存容量或替换策略

回答：

> 容量通过StorageService/PageCache构造参数传入；策略只应修改PageCache内部顺序维护，不修改PageFile和上层数据库接口。修改后用固定访问串比较resident、hit、miss和eviction。

### 4 增加一列输出

回答：

> 如果只是SELECT中增加已有列，不改代码；Parser已经支持列列表，Semantic检查列存在，Project按columns输出。如果是增加新的系统目录字段，则要同步修改SYSTEM_SCHEMA、rows()、RecordCodec数据和加载逻辑。

## 十一 三人个人高频问题

### 成员A

1. Token与AST有什么区别？
   - Token是线性词法单元；AST是带层次和语义结构的树。
2. 为什么用递归下降？
   - 文法规模小，代码与文法对应，容易定位错误和扩展。
3. 为什么不能有左递归？
   - 会在未消费Token前反复调用自身，导致无限递归。
4. match与expect的区别？
   - match处理可选内容，失败不移动；expect处理必选内容，失败报错。
5. Parser为什么不检查列存在？
   - Parser只检查文法，列存在依赖当前Catalog，属于语义分析。
6. AST与Plan为什么分开？
   - AST描述用户写了什么；Plan描述数据库怎样执行。
7. 为什么Sort在Project之前？
   - ORDER BY可能使用最终不输出的列。
8. 优化前后怎样保证结果相同？
   - 只使用可证明等价的规则，并保留对比测试。

### 成员B

1. 为什么是固定4KB页？
   - 统一磁盘、缓存、WAL和分配管理单位，并贴近操作系统页概念。
2. offset如何计算？
   - `page_id×4096`。
3. LRU与FIFO差别？
   - LRU命中会更新最近使用顺序；FIFO命中不改变进入顺序。
4. dirty是什么意思？
   - 内存页比磁盘页新，淘汰或Checkpoint前必须回写。
5. pin为什么必要？
   - 防止正在使用的页面被淘汰。
6. WAL为什么先于数据页？
   - 保证数据页落盘前已有可用于恢复的日志。
7. redo为什么可以重复执行？
   - 比较generation，只在磁盘版本较旧时重放。
8. 当前恢复有什么边界？
   - 是页级redo，不提供多语句事务Undo和原子回滚。

### 成员C

1. RID是什么？
   - 页号与槽号组成的记录物理标识。
2. 为什么使用SlottedPage？
   - 支持变长记录，记录移动时通过槽间接定位。
3. first_page在哪里？
   - TableSchema中，由Catalog持久化。
4. 页链怎样遍历？
   - 从first_page开始读取每页next_page，直到NO_PAGE。
5. DELETE为什么文件不立刻变小？
   - 当前使用槽位逻辑删除，没有实现压缩与vacuum。
6. UPDATE变长怎么办？
   - 原地更新失败则新插入并删除旧RID。
7. pg_catalog为什么从页0开始？
   - 数据库启动必须有固定目录入口。
8. Executor为什么不直接访问PageFile？
   - 必须经过TableHeap、SlottedPage、Buffer和PageStore接口，保持分层并获得缓存与恢复能力。
