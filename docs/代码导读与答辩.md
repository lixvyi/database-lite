# 代码导读与答辩提纲

本文按代码段职责解释源码。答辩时应能从入口追到返回值，并对教师随机指定的具体行说明变量状态。

## Lexer

- `peek/advance` 分别观察和消费；`advance` 是行列号唯一修改点。
- 主循环先处理空白/注释，再进入标识符、数字、字符串、分隔符或操作符分支。
- 消费首字符前保存 `start`，所以报错位置稳定。
- SQL 两个连续单引号解码为一个内容单引号。

## Parser

- `match` 可选消费，`expect` 必须消费并产生期望集合。
- 每个语句函数只负责对应文法。
- `or_expr → and_expr → not_expr → comparison` 的调用方向就是优先级来源。
- 左结合通过循环把旧树作为新 BinaryExpr.left 实现。

## Semantic / Catalog

- CREATE 检查重复列；其他语句先绑定表。
- `expr` 递归返回类型并回填 `inferred_type`。
- 名字、列数和类型错误在执行前停止。
- PagedCatalog 同时是编译器符号表和存储物理目录，固定保存在页 0，是三模块接口中心。

## Plan / Optimizer

- SELECT 从 SeqScan 开始，外包可选 Filter、Sort 和 Project；UPDATE 外包 Filter 与 SeqScan。
- Optimizer 深拷贝，避免修改“优化前”证据。
- `fold` 仅在操作数均为常量时求值，并应用安全布尔恒等式。

## Page

- Header 描述页元数据；Slot 描述记录位置。
- `insert` 检查 payload+slot 空间，移动 free_end，写记录、槽、页头。
- `delete` 只把 slot.length 置零，RID 保持稳定。
- `records` 跳过 tombstone。

## OS PageFile / Cache / WAL

- `PageFile` 中的 `seek(page_id*4096)` 是页号到物理字节的映射点。
- LRU 命中将页移到尾部，FIFO 命中不改变顺序；淘汰都从头找首个未 pin 页。
- `PageCache.update` 先追加并 fsync WAL，再把 frame 标脏。
- dirty 页淘汰前写回；写回前检查 page_lsn 不得越过 durable_lsn。
- `OSBufferAdapter` 是 TableHeap 与独立 StorageService 的唯一适配边界。

## Execution / Auth

- `evaluate` 递归计算表达式，不解析 SQL。
- TableHeap 隐藏页链和行编码，使执行器面向行与 RID。
- `_rows` 是 iterator model：算子从子节点逐行拉取。
- Sort 物化子结果并做稳定多键排序；Update 先锁表，再以原行计算所有赋值。
- 权限在执行前检查动作和列，行过滤在 SeqScan 输出处执行。

## 高频现场问题

1. 为什么 `a=1 OR b=2 AND c=3` 的根是 OR？
2. 为什么语义错误不能留到执行器？
3. 页内删除为何不立即压缩，代价是什么？
4. 8 页缓冲池扫描 100 页会发生什么？
5. 常量折叠如何证明不改变结果，加入 NULL 后哪里要改？
6. 表锁升级为行锁后，死锁为何出现？
7. 列权限和行权限为何要在 Project 前考虑？
